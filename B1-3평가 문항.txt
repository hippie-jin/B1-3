기능 동작 검증

 [프로젝트 1] 2개 이상의 도구에서 동일 워크플로우를 구현했는가? (툴별 구성 화면 + 실행 결과 스크린샷이 있는가?)

 [프로젝트 1] 비교 분석 보고서가 제출되었는가(PDF 또는 Markdown)?

 [프로젝트 1] 비교 분석 보고서에 최소 5개 이상의 비교 항목이 포함되어 있는가?

 [프로젝트 2] Trigger 발생 시 수동 개입 없이 자동으로 실행되는가?

 [프로젝트 2] Trigger 1개 이상, Action 2개 이상, 조건 분기 1개 이상이 포함되어 있는가?

 [공통] 제출물에 토큰/API Key/비밀번호 등 민감정보가 노출되지 않았는가?

동작 구조 및 설계

 [프로젝트 1] 두 도구에서 동일성(입력 이벤트/핵심 Action/분기/최종 출력)을 맞추기 위해 어떤 설계 기준을 적용했는지 설명할 수 있는가?
 [프로젝트 2] 워크플로우를 "Trigger → Action → 분기 → 출력" 구조로 설명할 수 있는가(단계별 입력/출력 포함)?
 [프로젝트 2] 조건 분기(Filter/Router)를 어떤 기준으로 설계했는지 설명할 수 있는가?

핵심 기술 원리 적용

 Trigger와 Action의 차이를 예시와 함께 설명할 수 있는가(왜 Trigger가 "시작점"이고 Action이 "처리"인지)?

 비교한 도구들의 차이를 "업무 요구사항" 관점으로 연결해 설명할 수 있는가(예: 협업/운영/디버깅/확장/비용)?

 프로젝트 2에서 특정 도구를 선택한 이유를 비교 항목 2개 이상과 연결해 설명할 수 있는가?

심층 인터뷰

 트리거가 불안정하거나 외부 연동이 자주 실패한다면 어떤 방식으로 모니터링/재시도/대체 경로를 설계할지 설명할 수 있는가?
 조건 분기 규칙이 늘어나거나(분기 2개→5개) 처리 로직이 복잡해진다면 워크플로우를 어떻게 구조화/모듈화할지 설명할 수 있는가?
